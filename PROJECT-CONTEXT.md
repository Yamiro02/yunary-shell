# PROJECT-CONTEXT.md — @yunary/shell

> Contexte du package **coque** de la coquille web Yunary. Yunary en général → `../../../PROJECT-CONTEXT.md`. Données → `../../supabase/PROJECT-CONTEXT.md`. Le hub qui le monte → `../../hub/PROJECT-CONTEXT.md`.
> Repo GitHub `Yamiro02/yunary-shell` cloné ici, installé **épinglé** dans le hub. Dépend de `@yunary/ds`. L'API symbole par symbole → `EXPORTS.md`. Un état, pas un journal.

---

## 1. Rôle

Tout ce que la coquille web a en commun avec ce qui pourrait venir après (l'Admin) et ne doit **jamais** réécrire : la session partagée entre sous-domaines, l'auth côté client, le layout (sidebar, tiroir mobile), les pages Paramètres, auth et légales, le bilan d'audit, les hooks du modèle par outil (catalogue, droits, abonnement, règles, historique), les chaînes FR communes. Une app = `@yunary/ds` + `@yunary/shell` + ses pages.

**Aucune fondation ici** : couleurs, rayons, typo et composants génériques viennent du DS ; la coque compose avec les utilitaires Tailwind branchés sur ses jetons, sans CSS propre. Un manque du DS se signale dans son `BACKLOG.md`, avec la solution provisoire posée ici, jamais recréé comme fondation.

**État (27/09/2026) :** version **0.4.2** (0.4.2 : redirections d'auth en chemins internes, déconnexion sans `next`, mot de passe oublié sans l'adresse, unités de quota ; 0.4.0 : abonnement v2 câblé sur le § 8 du back, onglet Abonnement retiré, carte compte « N outils · X €/mois » ; 0.4.1 : inscription sans confirmation enchaînée sur la règle d'après connexion, `backLabel` de l'écran de retour) ; (tag `v0.3.2` ; 0.3.0 = le pivot MCP, 0.3.1 = checkout multi-outils, `showToolsLink`, `ToolLabel`, types du lot 1 ter, 0.3.2 = redirection après auth vers `/autoriser` avant l'onboarding, `next` sur tous les chemins d'auth), écrite pour le pivot MCP : plus de crédits, plus de registre d'outils, plus de page « Mes outils » applicative, plus de cartes du profil créateur, plus de variante native. Le hub est encore sur la **0.2.4** (tag épinglé) jusqu'à sa montée au lot 2.

## 2. Ce que le paquet est

- **`configureShell(config)`** — appelé une fois par l'app dans `main.tsx` : `supabaseUrl`, `supabasePublishableKey`, `hubUrl`, `cookieDomain` (absent en local), `stripePublishableKey` (fenêtre de paiement ; sans elle elle dit « paiement indisponible »), `extraNextOrigins` (ignoré depuis 0.4.2). Un paquet ne lit pas `import.meta.env`.
- **`supabase`** — client unique, `createBrowserClient` de `@supabase/ssr`, cookies `.yunary.com` en prod (`path '/'`, `sameSite 'lax'`, `secure`), absents en local. Flux PKCE : un lien de reset ouvert dans un autre navigateur est invalide, la page le dit et renvoie vers « Mot de passe oublié ». Singleton paresseux ; **la déconnexion passe par `signOut()` de ce client**. Aucune app ne crée son propre client ni ne touche au stockage de session.
- **Auth** (`src/auth/`) — pages A1-A4 + `/reset` (connexion, inscription, mot de passe oublié — après envoi, un seul message sans l'adresse, que le compte existe ou non (0.4.2) —, nouveau mot de passe, « vérifie ta boîte mail »), Google et Apple (`OAuthButtons`, marques SVG inline dans `BrandMarks.tsx` avec Instagram / TikTok), `ProtectedRoute` (non connecté ou `onboarding_completed = false` → `/login?next=<chemin>` ; après une déconnexion VOULUE, `/login` sans `next`), **`next` = chemin interne uniquement** (0.4.2 : « /… », jamais « // » ni une URL complète, même `*.yunary.com` ; `isSafeNext`, `buildLoginUrl`, `toInternalPath`), **`useLogout`** (`signOut` puis `/login` sans `next` ; `signOut()` marque la déconnexion comme voulue, `ProtectedRoute` le lit), `useAfterAuthRedirect` sur **`resolveAfterAuth`** (🔒 la règle, testée : a. `next` = `/autoriser…` — chemin exact, requête intacte — quel que soit l'onboarding, c'est le retour du consentement du connecteur Claude ; b. onboarding pas terminé → `/onboarding` ; c. `next` interne valide → `next` ; d. sinon `/outils` ; l'exception ne s'élargit à aucune autre route ; navigation client, jamais pleine page), **inscription sans confirmation par e-mail** (réglage Supabase de Julien, 25/09/2026) : `signUp` renvoie une session → la page enchaîne directement avec cette règle, « Vérifie ta boîte mail » ne reste qu'en secours ; **`next` conservé sur tous les chemins** (mot de passe, inscription avec ou sans confirmation — `emailRedirectTo` = `/login?next=` —, Google et Apple — `redirectTo` = `/login?next=` —, oubli → reset — `redirectTo` = `/reset?next=`, puis la règle après le nouveau mot de passe — et sur les liens entre pages via `withNextParam`, sans doubler celui que l'app pose), schémas zod (`passwordSchema` = politique du projet Supabase : 8 caractères, minuscule + majuscule + chiffre). **Le flux d'auth ne se modifie jamais sans demande explicite.** Décisions figées : A1 sans sous-titre (Julien, 08/09/2026, ne jamais réintroduire) ; A2 avec la mention légale « En t'inscrivant, tu acceptes les CGU et la politique de confidentialité » (décision juridique et funnel) ; aide du mot de passe sur le composant d'aide du DS et texte de la vraie politique ; A4 pastille `brand`, « Renvoyer l'e-mail » en `surface="card"` ; carte d'auth sur `max-w-dialog` (27,5 rem) ; jamais de `no-underline` sur un lien.
- **Compte** (`src/account/`) — `useAuth()`, `useProfile()` (`role`, `platform`, `handle`, prénom, nom), `useUpdateProfile`, `useAvatar`, `useDeleteAccount` (→ Edge `delete-account`), **`useSubscription()`** → `{ subscription: { status, currentPeriodEnd, cancelAtPeriodEnd } | null, items }` (`subscriptions` colonne-limitée hors ids Stripe + articles actifs de `subscription_items`), `useStripe` (portail, `useRemoveTool`, résiliation / réactivation).

## 4. Ce qu'une app doit faire

- Variables d'env, côté app : `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, `VITE_HUB_URL`, `VITE_COOKIE_DOMAIN` (`.yunary.com` en prod, vide en local), `VITE_STRIPE_PUBLISHABLE_KEY` — passées à `configureShell` dans `main.tsx`.
- Peers : `react`, `react-dom`, `react-router-dom`, `@yunary/ds` (≥ 0.1.5), `@tanstack/react-query` (le `QueryClient` est celui de l'app), `lucide-react`, `tailwind-merge`. `@stripe/*` et `@supabase/*` sont des dépendances du paquet.
- CSS d'entrée : `@import '@yunary/ds/theme.css';` puis `@source '../node_modules/@yunary/shell/src';`.
- Montage : `<QueryClientProvider>` + `<BrowserRouter>` ; routes protégées sous `<ProtectedRoute>` ; `<AppLayout>` en layout de route (avec `toolsHref` = la route de sa page des outils) ; `/parametres` → `<ParametresPage toolsHref>`.

## 5. Spécificités

- Paliers typographiques du DS uniquement : aucun palier inventé ni amputé. Écarts aux maquettes validés par Julien et figés : sidebar à `--sidebar-w`, gouttières de la v1 (16 / 24 px), Paramètres alignés sur C2-C5 le 08/09/2026 (titre d'abonnement en Onest 800, cartes et rangées en filet 1,5 px, libellés secondaires en `text-caption` 13 px — l'eyebrow ne va pas), modales sans pastille, checkout plein écran sur mobile (13/09/2026).
- **Composés faute de composant DS** (consignés dans `apps/packages/ds/BACKLOG.md`) : `SegmentedControl`, l'avatar utilisateur, les marques Google / Apple / Instagram / TikTok en SVG inline, la barre haute + tiroir en guise de tab bar mobile, le cadre défilant du checkout, le récap replié du checkout mobile (`<details>` natif). Le `ChoiceChip` est parti avec le profil : son entrée au backlog du DS reste valable si un écran en a besoin.
- Versionné et taggé ; une app monte de version volontairement (jamais `latest`). Entrée unique `@yunary/shell` (pas de sous-chemins).
